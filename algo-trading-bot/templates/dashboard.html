System Documentation & FAQ

                

                    

                        
1. System Overview & Architecture

                        

                            Delta Exchange Trading Bot is a production-grade algorithmic trading service designed to connect external signal providers (like TradingView strategies) with Delta Exchange accounts. By utilizing high-speed HTTP webhooks, the bot receives buy, sell, and exit signals and instantly executes the corresponding orders.
                        

                        

                            To ensure optimal execution speed and reliability, the bot is built on a concurrent background thread pool. Whenever an incoming webhook is validated, the trade execution logic is deferred to a background worker. This ensures that the HTTP response is returned immediately to TradingView (avoiding timeouts), while the API calls to Delta Exchange run asynchronously.
                        

                        

                            Additionally, the bot includes a local SQLite database that maintains structured logs of all incoming alert payloads, trade executions, circuit-breaker states, and account metrics. A clean, responsive administrative user interface leverages WebSockets or polling to feed real-time analytics to the dashboard, rendering live metrics, open positions, and account balances.
                        

                    


                    

                        
2. Webhook Setup & Pine Script Integration

                        

                            To configure your TradingView strategy to alert the bot, you must set the Webhook URL in the alert settings. The URL format requires your secure passphrase:
                        

                        
https://your-bot-host.onrender.com/webhook?passphrase=your_secret_passphrase
                        

                        

                            We recommend using Option A (Dynamic Sizing via Pine Script) for compounding strategies. In your Pine Script code, calculate the potential contract quantity using your current risk model, and construct a JSON payload to pass to alert_message inside the strategy.entry call:
                        

                        
string buyMsg = '{"action":"buy","ticker":"' + syminfo.ticker + '","quantity":' + str.tostring(qty) + '}'
strategy.entry("Long", strategy.long, qty=qty, alert_message=buyMsg)
                        

                        

                            Alternatively, you can utilize Option B (Fixed Sizing or Automatic Bot Sizing). If the quantity parameter is omitted from the incoming alert payload, the bot falls back to the configured sizing settings in the admin dashboard:
                        

                        
{
  "action": "buy",
  "ticker": "ETHUSD.P"
}
                        

                        

                            When no quantity is provided, the bot uses the active account's configured sizing mode: either a fixed percentage of available margin, a fixed USD size, or a fixed contract quantity. This offers high flexibility for non-coder users who want to configure rules entirely on the dashboard.
                        

                    


                    

                        
3. Position Sizing, Leverage & Buffer Calculations

                        

                            A key differentiator of this bot is its robust position sizing engine. When sizing calculations are requested, the bot executes a safety-first mathematical model to prevent accidental over-leveraging and liquidation risks:
                        

                        

                            Let \(B\) be the available wallet balance, \(L\) the configured leverage, \(S_b\) the safety buffer percentage (e.g., 95% or 0.95), and \(P_m\) the mark price of the contract. The maximum USD contract value we can trade is:
                            \[V_{max} = B \times L \times S_b\]
                            Given the contract multiplier (or lot value) \(C_v\) (for example, 0.01 for ETHUSD), the maximum quantity of lots is:
                            \[Q_{max} = \lfloor \frac{V_{max}}{P_m \times C_v} \rfloor\]
                        

                        

                            This formula ensures that even in volatile markets where the bid/ask spread widens, the order will not be rejected due to insufficient margin. By maintaining a safety buffer (typically 90% to 95%), you preserve a small cash cushion to cover initial margin requirements and negative slippage during execution.
                        

                    


                    

                        
4. Commission Fees & Realized PnL Calculations

                        

                            For professional traders, accurate profit and loss tracking is essential. The bot does not simply trust the gross profit numbers returned by the exchange; it computes a strict net PnL by accounting for execution commissions.
                        

                        

                            Every complete trade cycle includes an entry and an exit:
                        

                        
    
                            
  • Entry Fee: Estimated using the configured maker/taker fee rate (default is 0.05% or 0.0005 of position value) or extracted from the order transaction history.
    • 
                            
  • Exit Fee: Retried dynamically from the Delta Exchange API's paid_commission field on the closed position order.
    • 
                            
  • Net PnL: Calculated as: \(\text{Net PnL} = \text{Realized PnL} - \text{Entry Fee} - \text{Exit Fee}\).
    • 
                        

                        

                            Currency Conversions: For users operating on Delta Exchange India (which transacts in Indian Rupees - INR), the bot automatically normalizes all values. It detects the endpoint suffix, retrieves the balance/PnL/fees in INR, and divides them by a configured stable rate of 85.0 to represent all metrics in USD/USDT on the dashboard, preventing currency mixing errors.
                        

                    


                    

                        
5. Risk Management & Drawdown Circuit Breakers

                        

                            To protect capital during market anomalies or strategy degradation, the bot contains dual-layered local risk controllers:
                        

                        

                            

                                
Daily Drawdown Circuit Breaker

                                

                                    If the combined net PnL of all trades completed on a calendar day falls below the user-specified daily loss limit (e.g., -$100 USD), the circuit breaker triggers. It immediately closes all open positions on Delta Exchange, cancels any active orders, and blocks further webhook entry alerts until the administrator manually resets the lock status.
                                

                            

                            

                                
Consecutive Losses Circuit Breaker

                                

                                    If your strategy experiences a sequence of consecutive losing trades that exceeds the set threshold (e.g., 5 losses in a row), the system will automatically pause execution. It sends an emergency email alert to the administrator and enters a paused state, requiring a manual review of strategy performance before trading can resume.
                                

                            

                        

                    


                    

                        
6. Frequently Asked Questions (FAQ)

                        
                        

                            
Q: How does the bot handle reversals and exit orders?

                            

                                A: If the bot receives a trade entry signal in the opposite direction of an active position (e.g., a "buy" signal while short), it automatically detects the reversal. It will first place a market order to close the opposing position, wait 1.5 seconds for margin release, and then execute the entry order in the new direction.
                            

                        


                        

                            
Q: Can I connect multiple Delta Exchange accounts to the same bot?

                            

                                A: Yes! The bot supports multi-account management. You can add, edit, and configure multiple API keys in the dashboard. Webhooks can target specific accounts by adding the account parameter (e.g., &account=Test Account 1) to the webhook URL.
                            

                        


                        

                            
Q: How do I verify that webhooks are successfully reaching the bot?

                            

                                A: Go to the "Alert Playground" tab in the dashboard. You can send test payloads to verify connection speed, check if the passphrase matches, and see how the bot would parse and size the trade without actually submitting orders to the exchange.
                            

                        


                        

                            
Q: What happens if Delta Exchange APIs go down or experience latency?

                            

                                A: The bot includes built-in retry mechanisms and HTTP timeout policies. If an API request fails due to rate limits or network hiccups, the bot will retry the request with exponential backoff. If it remains unreachable, the trade is marked as "failed" in the dashboard logs, and you will receive an email notification.
                            

                        

                        
                        

                            
Q: How is my API key information secured?

                            

                                A: API keys are encrypted at rest using AES-256 encryption. Access to the dashboard is protected by dynamic session authentication. In addition, the bot enforces security headers such as Content-Security-Policy (CSP) and HTTP Strict Transport Security (HSTS) to prevent cross-site scripting and man-in-the-middle attacks.
